# Frontend Review Checklist

A frontend change is review-ready when:

- [ ] The requirement is clear.
- [ ] Existing frontend patterns are followed.
- [ ] Affected components/routes/services are listed.
- [ ] API/data contract assumptions are documented.
- [ ] Loading, empty, success, and error states are covered.
- [ ] Form validation is covered if relevant.
- [ ] Accessibility basics are considered.
- [ ] Build/test/lint commands are listed or discovery is assigned.
- [ ] Regression areas are identified.
- [ ] Handoff is clear.
