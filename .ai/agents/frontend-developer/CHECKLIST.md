# Frontend Developer Checklist

## Frontend Change Readiness

- [ ] Requirement or story is clear.
- [ ] Acceptance criteria are understood.
- [ ] Existing UI pattern is identified.
- [ ] API/data contract is understood.
- [ ] Affected components are identified.
- [ ] Affected routes are identified.
- [ ] Affected services/API clients are identified.
- [ ] Tests or validation commands are known.
- [ ] .ai/locks has been checked.

## UI State Coverage

- [ ] Loading state
- [ ] Empty state
- [ ] Success state
- [ ] Validation error state
- [ ] Server error state
- [ ] Permission denied state, if relevant
- [ ] Disabled/read-only state, if relevant
- [ ] Refresh/retry behavior, if relevant

## Form Review

- [ ] Required fields are clear.
- [ ] Optional fields are clear.
- [ ] Validation rules are implemented.
- [ ] Error messages are user-friendly.
- [ ] Submit behavior is clear.
- [ ] Cancel/reset behavior is clear.
- [ ] API errors are handled.
- [ ] Save success feedback is shown.

## API Integration Review

- [ ] Endpoint is known.
- [ ] Request model is clear.
- [ ] Response model is clear.
- [ ] Error model is handled.
- [ ] Loading state is handled.
- [ ] Empty response is handled.
- [ ] API contract assumptions are documented.

## Accessibility / Usability

- [ ] Inputs have labels.
- [ ] Buttons have clear text.
- [ ] Keyboard usage is reasonable.
- [ ] Focus behavior is reasonable.
- [ ] Error messages are visible.
- [ ] Text is readable.
- [ ] Important actions provide feedback.

## Frontend Validation

- [ ] Build command run or recommended.
- [ ] Test command run or recommended.
- [ ] Lint command run or recommended.
- [ ] Manual UI validation steps listed.
- [ ] Regression areas identified.
