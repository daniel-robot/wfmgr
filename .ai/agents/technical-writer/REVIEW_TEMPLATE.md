## Accuracy Review

Assess whether the documentation matches current implementation and validated facts.

Cover:

* Does the doc describe current behavior accurately?
* Does it distinguish completed work from planned work?
* Does it avoid unsupported claims?
* Does it reference correct file paths?
* Does it avoid stale session context?

## Clarity Review

Assess whether the document is easy to read and useful.

Cover:

* Clear purpose
* Clear audience
* Clear structure
* Actionable instructions
* Concise wording
* No unnecessary repetition

## Safety Review

Assess whether the documentation avoids risky guidance.

Check:

* No secrets
* No production credentials
* No destructive commands without warnings
* No unapproved deployment instructions
* No generated docs edited manually
* No unsupported compliance claims
